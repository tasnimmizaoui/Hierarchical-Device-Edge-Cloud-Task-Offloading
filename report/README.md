# IEEE article

This directory contains the revised IEEE article for the hierarchical
device--edge--cloud offloading project. It uses the repository's canonical
SimPy backend and incorporates the documented Alibaba-derived DQN/Double-DQN
campaign without modifying simulator or RL source code.

## Compile

From the repository root, with a TeX installation and `latexmk` available:

```bash
python3 report/plot_final_results.py
cd report
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

The output is `report/main.pdf`. If `latexmk` is unavailable, run `pdflatex`
twice and then `bibtex main`, followed by two more `pdflatex` runs.

## Experimental inputs

The six-policy comparison uses the verified data under
`docs/experiments/final-matched/`. The supplementary centralized Double DQN
control uses the `centralized_rl` rows from the five frequent-feedback
Double DQN bundles, filtered to `alibaba2017_test`. The five evaluation
noise runs are averaged per training seed before computing means and
sample standard deviations. The task IDs and arrival times match the
primary comparison for all 25 replays.

The architecture figures are explanatory diagrams. The DQN/Double-DQN,
topology, and feedback figures plot only means documented in
`docs/rl_experiment_report.md`; they are not independently regenerated from
local campaign CSV files.

The matched-policy figure reads the means and sample standard deviations in
`docs/experiments/final-matched/summary.csv`. The latency exceedance figure
uses the compressed per-task CSV in the same directory. The workload figure
uses `workload_summary.csv`, generated by `scripts/explore_report_trace.py`
from the filtered Alibaba splits. The DQN layer diagram and topology diagram
document the model settings. Regenerating the article figures from these
inputs requires neither the raw Alibaba trace nor model checkpoints.
